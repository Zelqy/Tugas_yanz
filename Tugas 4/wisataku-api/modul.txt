1.3 Uraian Materi
1.3.1 Web Service dan API
Web Service adalah unit perangkat lunak yang dapat diakses melalui
jaringan menggunakan protokol standar, menyediakan fungsi tertentu bagi aplikasi
lain tanpa aplikasi tersebut perlu mengetahui detail implementasinya. API
(Application Programming Interface) adalah kontrak yang mendefinisikan cara
dua perangkat lunak berkomunikasi.
Sebagian besar web API modern berjalan di atas protokol HTTP, dengan
elemen penting: method (GET, POST, PUT, PATCH, DELETE), URL, header, body,
dan status code.
1.3.2 Gaya API: REST, GraphQL, SOAP, gRPC
Gaya API Karakteristik Cocok Untuk
REST Berbasis resource, method

API tujuan umum, paling populer

Lauret (2019) menegaskan bahwa desain API yang baik berorientasi
pada pengalaman developer (Developer Experience) yang menggunakannya bukan
sekadar berfungsi secara teknis. Haro (2023) menambahkan bahwa pemilihan gaya
API idealnya didasarkan pada pola konsumsi data consumer, bukan sekadar tren
teknologi.

1.3.3 Arsitektur Sistem Terdistribusi dan REST
REST dibangun di atas beberapa batasan arsitektural: client-server
(pemisahan UI dan logika/data), stateless (setiap request membawa seluruh
informasi yang dibutuhkan), cacheable, layered system, dan uniform interface.
Subramanian & Raj (2019) menjelaskan evolusi dari Service-Oriented Architecture
(SOA) menuju Resource-Oriented Architecture (ROA) sebagai fondasi filosofi REST.
Monolitik vs Microservices:
Aspek Monolitik Microservices
Struktur kode Satu basis kode Terpisah menjadi layanan kecil
Deployment Satu unit Independen per layanan
Skalabilitas Skala seluruh aplikasi Skala per-layanan
Cocok untuk Tim kecil, tahap awal Aplikasi besar, tim terpisah
Haro (2023) menyarankan agar pemecahan microservices dilakukan
berdasarkan batas domain bisnis (bounded context), bukan lapisan teknis
misalnya “Layanan Destinasi” dan “Layanan Reservasi”, bukan “Layanan Database”
dan “Layanan API”.
1.3.4 Mengapa NestJS untuk Web Service Modern?
NestJS adalah framework Node.js yang dibangun di atas TypeScript,
menyediakan arsitektur modular berbasis Dependency Injection (terinspirasi
Angular), sehingga kode backend terstruktur rapi ke dalam Module, Controller, dan
Provider (Service) sangat cocok untuk membangun web service yang berkembang
dari monolitik menjadi microservices, karena batas modulnya sudah jelas sejak awal.
Struktur dasar NestJS:
src/
├── main.ts # Titik masuk aplikasi
├── app.module.ts # Root module
├── destinasi/
│ ├── destinasi.module.ts
│ ├── destinasi.controller.ts # Menangani HTTP request (routing)
│ └── destinasi.service.ts # Berisi logika bisnis
Contoh Controller paling sederhana untuk memahami alur request-response di
NestJS:
// src/destinasi/destinasi.controller.ts
import { Controller, Get } from '@nestjs/common';
@Controller('destinasi')
export class DestinasiController {
@Get()
findAll(): string {
return 'Daftar destinasi wisata akan tampil di sini';
}
}

async register(nama: string, email: string, password: string) {
const existing = await this.prisma.user.findUnique({ where: {
email } });
if (existing) throw new ConflictException('Email sudah

const passwordHash = await bcrypt.hash(password, 10);
const user = await this.prisma.user.create({

});

}

const user = await this.prisma.user.findUnique({ where: { email
} });
if (!user || !(await bcrypt.compare(password,
user.passwordHash))) {
throw new UnauthorizedException('Email atau password salah');
}
const payload = { sub: user.id, role: user.role };
return { access_token: this.jwtService.sign(payload),
token_type: 'Bearer' };
}

context.getHandler());

resource ini');
}
return true;
}

import * as request from 'supertest';
describe('Alur Lengkap Wisatawan WisataKu (e2e)', () => {
const gatewayUrl = 'http://localhost:3000';
let token: string;
let destinasiId: number;
it('1. Registrasi wisatawan baru', async () => {
const res = await
request(gatewayUrl).post('/auth/register').send({
nama: 'Siti',
email: 'siti@example.com',
password: 'rahasia123',
});
expect(res.status).toBe(201);
});
it('2. Login dan menerima token JWT', async () => {
const res = await request(gatewayUrl).post('/auth/login').send({
email: 'siti@example.com',
password: 'rahasia123',
});
expect(res.status).toBe(200);
token = res.body.access_token;
});
it('3. Mencari destinasi kategori Pantai', async () => {
const res = await
request(gatewayUrl).get('/destinasi?kategori=Pantai');
expect(res.status).toBe(200);
destinasiId = res.body[0].id;
});
it('4. Membuat reservasi dengan token yang valid', async () => {
const res = await request(gatewayUrl)
.post('/reservasi')
.set('Authorization', `Bearer ${token}`)
.send({ destinasiId, tanggalKunjungan: '2025-12-25',
jumlahTiket: 2 });
expect(res.status).toBe(201);
});
it('5. Admin (tanpa token wisatawan) ditolak menghapus destinasi',
async () => {
const res = await request(gatewayUrl)
.delete(`/destinasi/${destinasiId}`)
.set('Authorization', `Bearer ${token}`); // token wisatawan,
bukan admin
expect(res.status).toBe(403);
});
});

# WisataKu API
Backend API untuk platform informasi dan reservasi destinasi wisata,
dibangun dengan NestJS, Prisma ORM, dan MariaDB.
## Arsitektur
- API Gateway (NestJS) — port 3000
- Service Destinasi (NestJS + Prisma) — port 5001 (internal)
- Service Reservasi (NestJS + Prisma) — port 5002 (internal)
- MariaDB — port 3306
## Menjalankan Proyek
docker compose up --build -d
## Dokumentasi API
- REST (Swagger): http://localhost:3000/api/docs
- GraphQL (Apollo Sandbox): http://localhost:3000/graphql
## Menjalankan Pengujian
npm run test # unit test
npm run test:e2e # end-to-end test
## Autentikasi
Sertakan header `Authorization: Bearer <token>` untuk endpoint yang
memerlukan login. Dapatkan token melalui `POST /auth/login`.
## Versi API
- `/v1/destinasi` — struktur data lama (hargaTiket), didukung hingga 31 Des 2025
- `/v2/destinasi` — struktur data baru (hargaDewasa, hargaAnak)
